## Corrections to the record

1. **The 2026-09-05 business plan was drafted from a pre-2026-09-04 snapshot.**
   It treats real-model testing as still ahead and asks to add metrics that
   already exist. CM-E003 and CM-E004 have both RUN (see RESULTS-CM-E003.md,
   RESULTS-CM-E004.md). The plan's *direction* (heterogeneous model families,
   independence rule, correlated failure as primary target) is independently
   CONFIRMED by those results; its *facts* are superseded by them.
2. **Parked mechanisms stay parked.** Per RESULTS-CM-E003 (real models):
   reputation routing measured inert; provenance invalidation structurally
   inert on this task shape (no evidence either way); 10% audits marginal
   (~18 calls per catch); the arbitration 2-2 tie-break measurably harmful
   (75% wrong); spawning/retirement/topology never implemented in CM-0.1.1
   and never validated. The 2026-09-04 panel decision stands (revive only
   with a structurally-testable task family). Roundtable vote 3-0. The
   measured survivors: blind independent verification, re-verified retries,
   cross-family verifier.
3. **Provider reality.** The CLI subscriptions were refunded 2026-08-28, but
   both roundtable CLIs demonstrably run headless at $0 as of 2026-09-05:
   codex CLI 0.147.0 under Shane's OpenAI login, gemini CLI 0.55.1 via the
   free AI Studio key in `~/.gemini/.env` (Google discontinued the CLI's
   free OAuth tier — account is fine, that sign-in path is dead). Any PAID
   cloud experiment arm (API keys) is new spend requiring Shane's explicit
   approval. Plan configs naming Claude+Gemini+Codex as experiment seats
   must be recast onto available free seats (Claude + local families).
4. **Cost-accounting nit:** Arm B main-run cost is $1.2004 by completed-run
   ledger (runs.jsonl) and $1.30 by invocation log; the ~$0.10 delta is
   inferred from log-minus-ledger and consistent with the 7 timed-out
   attempts in failures.jsonl (which records no per-attempt cost). Quote
   $1.30 "(incl. resume overhead)" or $1.20 "(completed-run ledger)" —
   never bare mixed use.

## Decisions (roundtable 3-0 on each, 2026-09-05)

- Product story is built only on measured survivors; docs must mirror
  empirical reality ("parked", not "experimental").
- Experiment first, full docs rewrite after its result.
- Next experiment: CM-E005a capability-matched cross-family verifier
  (decorrelation vs capability isolation) — draft pre-registration in
  PREREG-CM-E005A-DRAFT.md (v2, post-adversarial-verification; expected
  Claude spend ≈ $5.3, hard campaign cap $8), **pending Shane's approval;
  nothing runs before that approval.** The free 10x all-local replication
  (CM-E004 rec 2) is deferred, not dropped — contingent follow-up per the
  prereg's "Relation to other candidates".
- Moat posture now: credibility + execution (publish finding, keep production
  code and accumulated per-family outcome ledger private). Start the free
  family-labeled verified-outcome ledger as a byproduct of E005a
  (results/ledger/family_outcomes.jsonl; schema in the prereg).
- New binding cost-control rules (all seats, unanimous):
  worst-case cost table in every pre-registration; pilot in the EXACT final
  configuration sampling the longest expected step; extrapolated upper bound
  (retries, context growth, failure paths) shown to Shane before the main
  run; per-invocation hard caps never raised; automatic kill-switch aborting
  the run if rolling cost/call exceeds 1.5x the pilot estimate (or any
  single call 3x); per-call spend logged continuously to
  runs.jsonl/steps.jsonl; any scope or config change requires a fresh
  estimate and re-approval; any cloud-API arm is a separate approval line
  item.

## Commercial posture (adopted from the reviewed plan, corrected)

Two-layer split: publish the research finding + methodology (credibility,
priority timestamp); keep production implementation, integrations, and the
accumulated per-family performance ledger private. BYO model access for
customers means API keys or local models — never consumer-subscription CLIs
(terms-of-service risk). No customer outreach until the finding is reproduced
and holds on a second task family.
